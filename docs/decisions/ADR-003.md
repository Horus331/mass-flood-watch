# ADR-003: Immutable archive of forecasts and observations

Status: accepted 9 Nov 2026; in progress. Last reviewed 11 Nov 2026.

## Context
The forward test (forecasts archived before each real storm, Nov 2026 – Oct 2027) is the strongest evidence the project can have, and only
if nobody can change a forecast after the fact.

## Decision
- Every issued forecast gets a compact file per issue time (segment, k of N, depth, onset, duration, driver) and a manifest (input sources
  and their run times, git SHA, container hash, parameters). Observations (MRMS QPE, gauges, NWS alerts and storm reports, Mass511 when
  allowed, Waze when available) are archived too.
- Primary store: the public Hugging Face dataset **mohabeldokla/mass-flood-watch-archive** (created 9 Nov 2026). Monthly snapshots to
  Zenodo (DOI).
- Until the scoped token `HF_ARCHIVE_TOKEN` exists as a GitHub Actions secret, forecasts keep being archived in the repo
  (`docs/proto/archive/`, `proto/storm_archive.py`), which is already append-only in git history.

## Consequences
The writer must never overwrite a past issue time (check before upload). Mass511 data are archived only if its terms allow research use
and storage (to check once Mo registers).
